# Feature Specification: Server Connections and Music Libraries

**Feature Branch**: `baseline/server-library`

**Created**: 2026-10-30

**Status**: Implemented baseline

**Input**: Existing Feishin product behavior, documented in `README.md` and the API/architecture guidance.

## User Scenarios & Testing

### User Story 1 - Connect to a music server (Priority: P1)

As a listener, I can configure and select a supported music server so Feishin can access my music library.

**Why this priority**: A server connection is required for server-backed library and playback workflows.

**Independent Test**: Configure a supported server and verify that the authenticated session can load server-backed content.

**Acceptance Scenarios**:

1. **Given** a supported server and valid connection details, **When** I configure and select it, **Then** Feishin can load content from that server.
2. **Given** configured servers, **When** I select another server, **Then** subsequent server-backed content is associated with the selected server.

### User Story 2 - Browse a music library (Priority: P1)

As a listener, I can browse and search music provided by my selected server using Feishin's shared library experience.

**Why this priority**: Finding music is the primary workflow after connecting a server.

**Independent Test**: Browse library sections and search for an item available on the selected server.

**Acceptance Scenarios**:

1. **Given** a selected server with library content, **When** I open a library section, **Then** Feishin presents the available content for that section.
2. **Given** a selected server with searchable content, **When** I search for a known item, **Then** matching results are shown.

### User Story 3 - Use server-specific capabilities (Priority: P2)

As a listener, I can use additional capabilities when my selected server supports them.

**Why this priority**: Server integrations differ, and supported capabilities should be available without implying universal support.

**Independent Test**: Verify a documented server-specific feature on its supported server and confirm unsupported capabilities are not presented as universally available.

**Acceptance Scenarios**:

1. **Given** a Navidrome server, **When** I open smart playlists, **Then** the Navidrome smart playlist editor is available.
2. **Given** a server without a capability, **When** I use the corresponding workflow, **Then** Feishin does not treat that capability as universally supported.

## Edge Cases

- A configured server is unavailable or rejects the connection.
- A server does not implement an endpoint used by an optional capability.
- The same library workflow receives different server-specific data shapes.

## Requirements

### Functional Requirements

- **FR-001**: Feishin MUST support connections to Jellyfin, Navidrome, and Subsonic-compatible music servers.
- **FR-002**: Users MUST be able to configure and select a server connection.
- **FR-003**: Users MUST be able to browse and search music from the selected server.
- **FR-004**: Common library workflows MUST remain usable across supported server types where the corresponding capability exists.
- **FR-005**: Feishin MUST distinguish server-specific capabilities from capabilities available across all supported servers.
- **FR-006**: Authentication details MUST NOT be exposed in application diagnostics or logs.

### Key Entities

- **Server connection**: A configured endpoint and authentication context for a supported music server.
- **Library item**: Music or collection content made available by the selected server.
- **Server capability**: An optional operation supported by some server types but not necessarily all.

## Success Criteria

### Measurable Outcomes

- **SC-001**: A user can connect to each supported server type and reach its available library content.
- **SC-002**: A user can browse and search available music without needing to know the server's response format.
- **SC-003**: Server-specific features are identifiable as such and do not imply support on unrelated server types.
- **SC-004**: Connection credentials are absent from diagnostic output generated by server requests.

## Assumptions

- The user has access to a compatible, reachable music server and valid credentials.
- Server APIs determine which library items and optional capabilities are available.
- Smart playlist editing is server-specific; the README identifies it as a Navidrome feature.

## Current Implementation References

- `src/renderer/api/controller.ts` selects a backend controller for the active server and sanitizes diagnostic data.
- `src/renderer/api/{jellyfin,navidrome,subsonic}/` contains backend-specific API/controller implementations.
- `src/shared/api/{jellyfin,navidrome,subsonic}/` contains server types and normalization.
- `src/renderer/features/{albums,artists,genres,search,playlists,songs}/` owns library-facing workflows.
- `docs/agents/api.md` documents the API and normalization boundaries; `README.md` documents supported servers and Navidrome smart playlists.
